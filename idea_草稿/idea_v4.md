# Memory in Memory：研究思路简版

## 1. 研究定位

Memory in Memory（MiM）面向一类**由大语言模型负责记忆构建与记忆访问的智能体记忆系统**。

这类系统通常包含两个核心过程：

1. **记忆构建（Memory Construction）**：从历史交互中选择、抽取、整合和更新记忆；
2. **记忆访问（Memory Access）**：根据当前问题检索、筛选和组织相关记忆。

现有系统虽然具备基本读写能力，但默认策略可能重复产生相似错误，例如：

- 重要信息没有被写入；
- 旧信息被错误覆盖；
- 状态变化没有被正确保留；
- 相关记忆已经存在，但没有被检索出来；
- 检索到多个版本，却没有选择时间上正确的事实。

MiM 不重新设计底层记忆存储，而是在已有记忆系统之外增加一个**错误驱动的元记忆层**：

> 从失败轨迹中学习关于“如何正确构建和访问记忆”的可复用自然语言 Skill，并在未来相似情境中指导原有记忆系统。

因此，MiM 学到的不是新的用户事实，而是关于记忆操作的**程序性元记忆**。

---

## 2. 核心研究问题

MiM 关注以下问题：

> 当一个基于大模型的记忆系统产生错误答案时，能否根据原始对话、记忆状态、检索结果和执行轨迹，判断错误发生在记忆构建侧还是记忆访问侧，并将修复经验抽象为可复用 Skill？

核心假设是：

> 不同用户、任务和对话中出现的具体记忆错误，往往共享相似的失败模式；这些失败模式可以被抽象成自然语言经验，并迁移到未见过的案例中。

---

## 3. 系统抽象

MiM 将基座记忆系统抽象为两个由大模型驱动的模块。

### 3.1 记忆构建智能体

**Memory Construction Agent** 接收原始对话和已有记忆，负责生成新的记忆状态。

它可以完成信息选择、事实抽取、记忆新增或更新、冲突处理和历史状态保留。MiM 不规定其底层存储形式，也不规定固定操作集，只要求该模块能够接收自然语言 Skill 作为附加指导。

### 3.2 记忆访问智能体

**Memory Access Agent** 接收当前问题和记忆库，负责获得支持回答的记忆证据。

它可以完成查询形成、相关记忆检索、候选筛选、时间关系处理和多条记忆组织。MiM 同样不限定其具体检索算法，只要求该模块能够接收自然语言 Skill。

### 3.3 双技能库

MiM 分别维护：

```text
Construction Skill Bank
Access Skill Bank
```

二者分别指导记忆构建和记忆访问，避免把两类本质不同的错误混入同一个经验库。

---

## 4. 错误归因

当下游回答错误时，MiM 首先判断错误来源。

### 4.1 记忆构建错误

原始对话中存在目标信息，但当前记忆库中没有被正确保留。

常见情况包括：

- 应写未写；
- 写入内容错误；
- 后续更新时丢失；
- 新信息错误覆盖旧信息；
- 多条事实被错误合并；
- 状态变化缺少时间关系。

### 4.2 记忆访问错误

目标信息已经存在于记忆库中，但访问过程没有形成正确证据。

常见情况包括：

- 相关记忆没有被检索；
- 查询表达不充分；
- 候选召回不足；
- 检索到错误版本；
- 多条记忆没有被正确组合；
- 时间条件或实体关系没有被正确处理。

### 4.3 其他错误

如果正确信息已经被访问，但回答模型仍然推理错误，或者原始历史中不存在答案，则不应错误地更新 Construction 或 Access Skill。

因此，故障诊断至少区分：

```text
Construction Failure
Access Failure
Other / Invalid
```

MiM 只对前两类进行 Skill 学习。

---

## 5. Skill 的定义

MiM 中的 Skill 不是脚本，也不是确定性的工具调用流程。

它是一段可以被检索并注入大模型上下文的**自然语言记忆经验**，用于说明：

- 何种情况下容易发生某类错误；
- 普通处理为什么会失败；
- 遇到类似情况时应如何处理。

建议采用最小结构：

```yaml
skill_name: 技能名称

skill_description: >
  说明该 Skill 适用于什么情形、
  解决什么问题以及为什么需要它。

skill_content: >
  给 Construction Agent 或 Access Agent 的具体自然语言指导。
```

示例：

```yaml
skill_name: 按目标时间选择状态

skill_description: >
  当同一属性存在多个时间版本，
  且问题询问当前状态或历史状态时使用。
  普通语义检索容易返回相似度较高但时间上无效的旧事实。

skill_content: >
  先识别问题要求的目标时间。
  当前问题应使用最新有效状态，
  历史问题应使用目标时间点有效的旧状态。
  不要因为存在更新状态而完全忽略历史状态。
```

其中，`skill_description` 主要用于检索，`skill_content` 主要用于指导大模型执行。

## 6. 从失败轨迹学习 Skill

### 6.1 首次生成

对于一个新错误，Skill Learner 首先根据失败轨迹独立生成一个 Draft Skill。

失败轨迹可以包括：

- 原始问题与错误答案；
- 正确答案或目标事实；
- 原始对话证据；
- 当前记忆状态；
- 正常构建或访问结果；
- 当前调用过的 Skill；
- 已知失败原因。

先独立生成 Draft 的目的，是避免新错误被已有 Skill 过早限制。

### 6.2 相似 Skill 检索与整合

生成 Draft 后，再从对应 Skill Bank 中检索相似 Skill。

Skill Learner 根据 Draft、失败轨迹和已有 Skill 进行增量管理：

- 新增新的 Skill；
- 修订已有 Skill；
- 合并高度重叠的 Skill；
- 复用已经足够的 Skill；
- 必要时淘汰长期无效或重复的 Skill。

具体 CRUD 机制可以参考 Mem0/MemGPT 风格的记忆管理，但属于实现细节。MiM 的核心是：

> 从具体失败中生成抽象经验，并通过与已有经验比较，使 Skill Bank 持续演化。

---

## 7. Candidate Skill 的回放验证

完成 Skill 整合后，系统得到 Candidate Skill，并根据错误归因回放到对应模块：

```text
Construction Failure → Construction Agent
Access Failure       → Access Agent
```

### 7.1 强制验证

直接把 Candidate Skill 提供给对应 Agent，并重放原失败案例。

强制验证回答：

> 当模型一定看到该 Skill 时，Skill 内容本身能否修复错误？

如果强制验证失败，说明 Skill 内容仍然不完整、错误或过于模糊，需要继续细化。

### 7.2 自然验证

将 Candidate Skill 放入正常 Skill Bank，恢复正常 Skill 检索和路由。

自然验证回答：

> 在真实运行条件下，该 Skill 能否被正确检索、采用并发挥作用？

自然验证中的失败主要分为三类。

#### Skill 未被检索

通常需要修改：

- Skill description；
- 适用范围；
- Skill 检索表示；
- 与相似 Skill 的区分方式。

#### Skill 已被使用，但仍然失败

通常需要修改：

- Skill content；
- 指导的具体性；
- 遗漏的条件；
- 错误或过宽的处理原则。

#### 当前错误被修复，但产生回归

说明 Skill 可能过度泛化，需要收紧适用条件，而不是简单增加更多内容。

---

## 8. 失败后的继续学习

Candidate 验证失败后，需要追加新的失败轨迹：

```text
原始失败
+ 当前 Candidate Skill
+ Candidate 的生成与修改过程
+ 是否被检索
+ 是否被实际使用
+ 强制验证结果
+ 自然验证结果
+ 新的失败原因
```

下一轮 Skill Learner 基于这些信息继续修订。

因此，Skill 的演化过程不是反复从零生成，而是：

```text
具体错误
→ 初步经验
→ 回放失败
→ 定位经验缺陷
→ 进一步细化
→ 形成更稳定的抽象经验
```

这种“失败—修复—再失败—再抽象”的轨迹，构成 MiM 所学习的核心元记忆。

## 9. 完整闭环

```text
历史对话
    ↓
Memory Construction Agent
    ← Construction Skill Retrieval
    ↓
Memory DB
    ↓
Memory Access Agent
    ← Access Skill Retrieval
    ↓
Answer Model
    ↓
下游反馈
    ↓
Failure Diagnoser
    ↓
Construction Failure / Access Failure / Other
    ↓
Skill Learner
    ↓
生成 Draft Skill
    ↓
检索相似 Skill 并增量整合
    ↓
Candidate Skill
    ↓
回放到对应 Construction / Access Agent
    ↓
强制验证 + 自然验证
    ↓
成功：接纳进入 Skill Bank
失败：追加失败轨迹并继续细化
```

## 10. 与 MemSkill 的关系

MiM 可以参考 MemSkill 的两项设计：

1. 使用简短描述表示和检索 Skill；
2. 使用较完整的自然语言内容指导大模型执行。

但两者的研究重点不同。

MemSkill 主要研究如何演化记忆构建技能，其 Skill 构成记忆生成机制的一部分。

MiM 则定位为附加在已有记忆系统之外的错误驱动元记忆层：

- 基座即使没有 MiM Skill，也能够按照默认方式构建和访问记忆；
- MiM 从下游错误出发，先进行构建侧或访问侧归因；
- MiM 同时学习 Construction Skill 与 Access Skill；
- MiM 通过回放区分 Skill 内容失败和 Skill 检索失败；
- MiM 强调持续修复已有记忆系统，而不是重新定义完整记忆机制。

---

## 11. 核心实验思路

实验需要验证的不只是最终回答准确率，还要验证 Skill 是否真正完成错误修复和经验迁移。

### 11.1 端到端效果

比较：

```text
原始记忆基座
原始基座 + 失败案例检索
原始基座 + 全局反思提示词
原始基座 + MiM
```

观察 MiM 是否持续提升长期记忆问答性能。

### 11.2 故障归因

评估系统能否正确区分：

- 记忆构建错误；
- 记忆访问错误；
- 非记忆错误。

### 11.3 Skill 泛化

从部分失败案例学习 Skill，在未见用户、未见对话和未见错误实例上测试：

- 已有 Skill 能否被复用；
- 一条 Skill 能否修复多个案例；
- 新案例是否不再需要生成新 Skill。

### 11.4 检索与内容分解

分别统计：

- Candidate 强制提供后是否有效；
- Candidate 是否在自然运行中被检索；
- 被检索后是否真正修复错误；
- 失败来自 description 还是 content。

### 11.5 跨基座验证

在多个由 LLM 执行构建和访问的记忆系统上接入 MiM，以验证它学习的是通用自然语言记忆经验，而不是某个单一系统的提示词补丁。

---

## 12. 预期贡献

MiM 的主要贡献可以概括为：

1. 提出一种面向大模型记忆系统的错误驱动元记忆框架；
2. 将下游记忆错误分解为记忆构建错误和记忆访问错误；
3. 从失败轨迹中学习可检索、可修订、可复用的自然语言 Skill；
4. 通过强制验证和自然验证区分 Skill 内容失败与 Skill 检索失败；
5. 使已有记忆系统能够积累“如何正确记忆”的程序性经验，而不仅积累用户事实。

---

## 13. 一句话概括

> Memory in Memory 是一个附加在大模型记忆系统之外的错误驱动元记忆层：它从下游失败轨迹中诊断记忆构建或访问问题，学习自然语言 Skill，并通过回放验证不断细化这些 Skill，使记忆系统能够跨案例积累和复用“如何正确记忆”的经验。
